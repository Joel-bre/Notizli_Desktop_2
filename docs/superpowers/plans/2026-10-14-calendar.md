# Recorder × calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The desktop recorder names the calendar meeting in its "Record it?" box, says which meeting a recording is for (with "Not this meeting"), and tells the server on upload (release 0.3.0). The window and menu bar then show the meeting on now or next, and in-person meetings get a box at their start (release 0.4.0).

**Architecture:**
- `crates/core` gets a pure `calendar` module: the server's answer as types, the display line, and which meeting is now, next or due. It is unit-tested.
- `crates/core` also gets the API call, and the upload gets one optional field.
- The app gets `calendar.rs`: an in-memory cache of the server's answer, fetched on demand in 0.3.0 and also every 5 minutes in 0.4.0.
- The recording's meeting lives in its local `Meta` until the upload is accepted.
- The prompt box, the window and the tray read the cache. Nothing calendar-related can delay or start a recording.

**Tech Stack:** Rust 2021 workspace (`notizli-core`, `notizli-engine`, Tauri 2 app), `time` 0.3 (local offset works multi-threaded since 0.3.37), `reqwest` 0.13, serde. The window is plain HTML/CSS/JS (no build step). Tests: `cargo test` (core unit tests, `testserver` for HTTP).

**Spec:** [`docs/superpowers/specs/2026-10-14-calendar-design.md`](../specs/2026-10-14-calendar-design.md). Server contract: `docs/calendar-desktop-api.md` in `Joel-bre/callcap-claude`. **The server change ships first**: its plan is `docs/desktop-calendar-plan.md` in that repo.

## Global Constraints

- Never invitee names. The desktop only knows `id, title, start, end, joinType` per meeting, plus `available`, `connected` and `now`.
- No meeting title in any log line. Logs say counts or "one on now" at most.
- Upcoming meetings are kept in memory only. A recording's own meeting is kept in its `<id>.json` (`calendar_ref`, `calendar_line`) until the upload is accepted.
- Recording always starts first. The meeting is attached after, and only if the server answers within 5 s.
- Upload `title` stays the desktop default (`"<App> call — …"` / `"Desktop recording — …"`). The meeting goes in `calendar_event_id` only: `g:…`/`m:…` or `none`.
- Any calendar failure, including a `404` from an older server, means "no calendar" without any error shown.
- Nothing starts a recording without a click on Record (Art. 179ter StGB).
- Display line: `"<title> · HH:MM · <join>"`, where join is `Teams | Zoom | Google Meet | Webex | Online | In person or by phone`. `(no title)` becomes `Untitled meeting`. Titles over 48 characters are cut to 47 + `…`.
- Releases: 0.3.0 = Tasks 1–5, 0.4.0 = Tasks 6–9. Bump `version` in `Cargo.toml` **and** `app/package.json`.
- CI gate: `cargo clippy --workspace --all-targets` with no warnings, and `cargo test`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage named files only.

## Review Focus

1. **The server is slow or down when the box appears.** The box must appear at once, exactly as today, and only change if the answer comes while it is still showing the same call. Pinned by Task 4's manual check with a fake file that has `"now": null` (no change), and by the `still_asking` guard.
2. **The recording finishes, or "Not this meeting" is clicked, before the background fetch returns.** The late answer must not attach a meeting. The guard in `attach_now` (same recording id, `calendar_ref` still unset) covers it. The race is too short to reproduce by hand, so the Task 3 reviewer checks the guard in the code.
3. **An old recording `.json` (0.2.x) in `unsent/`** must still load and upload, without `calendar_event_id`. Pinned in Task 2 (`old_meta_without_calendar_fields_loads`).
4. **A long meeting title** must not push the box's buttons out of the 132-px box. Pinned in Task 1 (48-character cut) and by the nowrap/ellipsis CSS in Task 4.
5. **The laptop wakes 5 minutes after an in-person meeting started.** No box should appear (the 2-minute window), and never twice for one meeting. Pinned in Task 6 (`in_person_due` edges and the asked set).

```rust
//! The user's upcoming calendar meetings, as notizli.ch gives them to the
//! recorder: titles and times only, never who is invited. The app keeps them
//! in memory only (docs/superpowers/specs/2026-10-14-calendar-design.md).

use serde::Deserialize;
use time::format_description::well_known::Rfc3339;
use time::{OffsetDateTime, UtcOffset};

/// Longer titles are cut so the "Record it?" box keeps its buttons.
const MAX_TITLE: usize = 48;

#[derive(Debug, Clone, Default, Deserialize, PartialEq, Eq)]
pub struct Upcoming {
    /// The calendar is offered to this account.
    #[serde(default)]
    pub available: bool,
    /// At least one calendar is connected.
    #[serde(default)]
    pub connected: bool,
    /// The meeting a recording started now belongs to (the server's own rule);
    /// None when no meeting fits, two fit, or a calendar couldn't be read.
    #[serde(default)]
    pub now: Option<String>,
    /// In progress or starting within 3 hours, by start.
    #[serde(default)]
    pub meetings: Vec<Meeting>,
}

#[derive(Debug, Clone, Deserialize, PartialEq, Eq)]
pub struct Meeting {
    /// "g:…" / "m:…", sent back as `calendar_event_id` on upload.
    pub id: String,
    pub title: String,
    /// ISO 8601, UTC.
    pub start: String,
    pub end: String,
    /// teams, zoom, meet, webex, other — or None: no video link.
    #[serde(rename = "joinType", default)]
    pub join_type: Option<String>,
}

fn parse(s: &str) -> Option<OffsetDateTime> {
    OffsetDateTime::parse(s, &Rfc3339).ok()
}

impl Meeting {
    pub fn start_at(&self) -> Option<OffsetDateTime> {
        parse(&self.start)
    }

    /// No video link: in person or by phone, so call detection can't notice it.
    pub fn in_person(&self) -> bool {
        self.join_type.is_none()
    }

    /// "Weekly sync · 14:00 · Teams", the time in `offset` (the computer's zone).
    pub fn line(&self, offset: UtcOffset) -> String {
        let t = self.title.trim();
        let title = if t.is_empty() || t == "(no title)" {
            "Untitled meeting".to_string()
        } else if t.chars().count() > MAX_TITLE {
            format!("{}…", t.chars().take(MAX_TITLE - 1).collect::<String>())
        } else {
            t.to_string()
        };
        let join = match self.join_type.as_deref() {
            Some("teams") => "Teams",
            Some("zoom") => "Zoom",
            Some("meet") => "Google Meet",
            Some("webex") => "Webex",
            Some(_) => "Online",
            None => "In person or by phone",
        };
        match self.start_at() {
            Some(s) => {
                let s = s.to_offset(offset);
                format!("{title} · {:02}:{:02} · {join}", s.hour(), s.minute())
            }
            None => format!("{title} · {join}"),
        }
    }
}

impl Upcoming {
    pub fn meeting(&self, id: &str) -> Option<&Meeting> {
        self.meetings.iter().find(|m| m.id == id)
    }

    /// The meeting a recording started now belongs to, when the server is sure.
    pub fn now_meeting(&self) -> Option<&Meeting> {
        self.now.as_deref().and_then(|id| self.meeting(id))
    }
}
```

```rust
    /// The user's meetings in progress or within 3 hours: titles and times
    /// only. Any failure, including a server that predates the route, is an
    /// error the caller treats as "no calendar".
    pub async fn upcoming_meetings(&self, device_token: &str) -> Result<Upcoming, ApiError> {
        let resp = self
            .http
            .get(format!("{}/api/public/recorder/upcoming-meetings", self.base))
            .bearer_auth(device_token)
            .timeout(Duration::from_secs(5))
            .send()
            .await
            .map_err(network)?;
        if resp.status().is_success() {
            return resp.json::<Upcoming>().await.map_err(|e| ApiError::Server(format!("unexpected answer: {e}")));
        }
        let (status, msg) = read_error(resp).await;
        Err(match status {
            401 => ApiError::Unauthorized,
            _ => ApiError::Server(server_detail(status, &msg)),
        })
    }
```

```rust
//! The user's upcoming meetings from notizli.ch, in memory only: they name
//! the meeting in the "Record it?" box and tell the server which meeting a
//! recording is for. Meeting titles never go to the log.
//! Design: docs/superpowers/specs/2026-10-14-calendar-design.md.

use std::sync::Mutex;
use std::time::{Duration, Instant};

use notizli_core::calendar::{Meeting, Upcoming};
use tauri::{AppHandle, Manager};
use time::UtcOffset;

use crate::state::AppState;

/// A list younger than this is used as is (notizli.ch caches 2 minutes too).
pub const FRESH: Duration = Duration::from_secs(120);

#[derive(Default)]
pub struct CalendarState {
    latest: Mutex<Option<(Instant, Upcoming)>>,
}

impl CalendarState {
    pub fn cached(&self) -> Option<Upcoming> {
        self.latest.lock().unwrap().as_ref().map(|(_, u)| u.clone())
    }

    pub fn forget(&self) {
        *self.latest.lock().unwrap() = None;
    }

    fn keep(&self, u: &Upcoming) {
        *self.latest.lock().unwrap() = Some((Instant::now(), u.clone()));
    }
}

/// The meetings, fetched again when the list is older than `max_age`. None
/// when unpaired or notizli.ch didn't answer: the app then behaves as before.
pub async fn upcoming(app: &AppHandle, max_age: Duration) -> Option<Upcoming> {
    let state = app.state::<AppState>();
    if let Some(u) = fake() {
        state.calendar.keep(&u);
        return Some(u);
    }
    if let Some((at, u)) = state.calendar.latest.lock().unwrap().as_ref() {
        if at.elapsed() < max_age {
            return Some(u.clone());
        }
    }
    let token = state.token()?;
    match state.api.upcoming_meetings(&token).await {
        Ok(u) => {
            let on_now = if u.now_meeting().is_some() { "one on now" } else { "none on now" };
            log::info!("calendar: {} meetings, {on_now}", u.meetings.len());
            state.calendar.keep(&u);
            Some(u)
        }
        Err(e) => {
            log::info!("calendar not read: {e}");
            state.calendar.forget();
            None
```

```rust
/// A meeting with no video link just started: call detection can't notice
/// it, so ask here. Only while paired with the switch on, not recording, no
/// box showing; once per meeting; gone after 60 s like the call box.
pub fn maybe_ask_in_person(app: &AppHandle, up: &Upcoming) {
    let state = app.state::<AppState>();
    if state.is_recording() || current(app).is_some() || !state.settings.lock().unwrap().ask_on_calls {
        return;
    }
    let mut asked = state.calendar.asked.lock().unwrap();
    let Some(m) = up.in_person_due(time::OffsetDateTime::now_utc(), &asked) else { return };
    asked.insert(m.id.clone());
    drop(asked);
    log::info!("asking whether to record (a meeting with no video link started)");
    let id = m.id.clone();
    show(app, View::Ask { title: calendar::line(m), question: "Starting now. Record it?".into(), meeting: Some(id.clone()), from_calendar: true });
    let app = app.clone();
    tauri::async_runtime::spawn(async move {
        tokio::time::sleep(std::time::Duration::from_secs(60)).await;
        if matches!(current(&app), Some(View::Ask { meeting: Some(m), from_calendar: true, .. }) if m == id) {
            hide(&app);
        }
    });
}
```
